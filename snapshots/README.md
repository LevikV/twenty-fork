# Снимки конфигурации CRM

Два файла, которые снимаются с боевой базы и лежат в git:

| Файл | Что внутри | Размер |
|---|---|---|
| `workflows.json` | все воркфлоу, **все** их версии, шаги и исходники CODE-шагов | ~850 КБ |
| `metadata.json` | объекты, поля, вьюхи, группы, фильтры, сортировки, лейауты, роли | ~3.7 МБ |

Обновить: `python3 scripts/snapshot.py` из корня репозитория.
Файлы перезаписываются целиком — обычный `git diff` покажет, что изменилось.

## Зачем

- воркфлоу и метаданные живут **только в базе**; из репозитория приложений их не видно;
- при переносе на чистую установку это эталон: что должно быть в workspace;
- при разборе «куда делась автоматизация» видно, что было на дату снимка.

## Важно: воркфлоу несвязаны с таблицей `workflow`

На 15.11.2026 в `core."workflow"` 19 строк, а в `core."workflowVersion"` — 41 версия,
и **ни одна версия не привязана к строке воркфлоу** (ссылки ведут на удалённые строки).
6 версий при этом в статусе `ACTIVE`. Поэтому снимок берёт версии отдельно, в разделе
`unlinkedVersions`, а не только через родительские воркфлоу — иначе потерялась бы
ровно та логика, которая ещё работает.

## Как восстанавливать

**Полное восстановление сервера** — не из этих файлов, а из дампа базы
(`scripts/backup-db.sh`, ежедневно в `/opt/twenty-crm/backups`):

```bash
gunzip -c /opt/twenty-crm/backups/default-YYYYmmdd-HHMM.dump.gz \
  | docker exec -i twenty-db-1 pg_restore -U postgres -d default --clean --if-exists
```

**Перенос конфигурации в другой workspace** — автоматического импорта в Twenty нет.
Эти файлы читаются как эталон:

- объекты и поля (`metadata.json`) — воссоздаются приложениями на TypeScript SDK
  (`twenty-apps`) или вручную через UI;
- воркфлоу — вручную в визуальном конструкторе; код шагов лежит в `codeSources`
  (`source` — полный текст файла `src/index.ts`);
- вьюхи и лейауты — вручную либо скриптом через metadata API.

**Сверка после обновления** — переснять снимок и посмотреть `git diff`: любые
незапланированные изменения объектов, полей, вьюх или правил видны как обычный diff.

## Регламент

- после ручной правки воркфлоу или метаданных в UI — переснять снимок и закоммитить;
- перед обновлением версии Twenty — переснять снимок (это точка сравнения).
